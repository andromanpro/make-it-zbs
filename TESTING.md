# Проверка Make it ZBS

## Headless CI

На Windows с инструментами из [CONTRIBUTING.md](CONTRIBUTING.md):

```powershell
./tools/ci.ps1 -VerifyReleaseDll
```

Выполняются C#, OneScript, JavaScript, Python, coverage, npm audit, lint,
Release-сборки и проверка совпадения поставляемых бинарников. Два построения
с разными SourceRevisionId должны совпасть побайтово. OneScript распаковывается
из проверенного vendor-архива, без OVM и внешних библиотек. Платные запросы
в обычный CI не входят. Пропуски не считаются успешными тестами.

GitHub workflow `.github/workflows/ci.yml` использует `windows-2022`, закрепленные
инструменты и отдельную проверку portable-пакета. Он не публикует релиз,
не получает личные API-ключи и не подключается к внутреннему SonarQube.

## Интерактивные проверки

Нужен разблокированный рабочий стол. Тесты создают собственные окна и конфиги,
но могут временно менять фокус и буфер обмена: не работайте параллельно.

```powershell
./tools/ci.ps1 -VerifyReleaseDll -RunUiTests -RunWordSmoke -RunPaintSmoke
```

Word нужен только для `-RunWordSmoke`, Paint для `-RunPaintSmoke`. Проверяются
настройки, локализация, горячие клавиши, UIA, индикация, независимый DXGI/GDI
захват и нативный резерв результата. При недоступном UI тест должен упасть,
а не молча превратиться в пропуск.

Полные маршруты через настоящее приложение, настоящие AI-запросы и 1С
являются отдельными opt-in проверками. Они могут расходовать лимиты провайдера
и требуют простаивающего рабочего стола. Не запускать в личных чатах/документах.
Синтетические материалы: `docs/manual-smoke/samples`; краткий сценарий чатов:
`docs/manual-smoke/ai-chat-quick-check.md`.

## Portable и выпуск

```powershell
py -3.14 tools/build-release.py --version v0.5.0-beta.4
py -3.14 tools/verify-dist.py dist/MakeItZBS --run-probe
py -3.14 tools/collect-licenses.py --check
```

Проверка portable сверяет каждый файл с MANIFEST, запрещает личные данные,
заполненный ключ, mockAI и внешние OVM-библиотеки, проверяет лицензии и запускает
ядро/детектор/штатный JSON из поставленного runtime с пустым тестовым профилем.
Это не виртуальная машина Windows 11 и не замена интерактивной приемки.

Перед публикацией дополнительно нужны два одинаковых ZIP из одного commit,
новый успешный CI, интерактивное свидетельство на той же версии, проверка
публичного состава исходников и явно перечисленные ограничения beta.

Локальный Sonar запускается отдельно владельцем инфраструктуры после CI.
Его адреса и credentials не нужны публичным пользователям. Зеленый локальный
Gate не означает, что уже прошел новый серверный GitHub run.
