# OneScript.Windows

Первое выделение Windows-примитивов из Make it ZBS, `0.1.0-beta.1`.
Это самостоятельная .NET-компонента для **OneScript 1.9.4 / Windows x64 / net472**,
а не NativeAPI для платформы 1С. OneScript 2.x и Linux не проверены.

## Состав

- Unicode-текст буфера: чтение и запись из любого потока через постоянный STA.
- Снимок исходных native-форматов буфера в памяти, с ограничением 64 МБ.
- Запись при ожидаемой версии буфера. После `CloseClipboard` буфер открывается
  для проверки владельца HWND и дескриптора данных; только затем считывается
  новая версия. Чужая копия не присваивается нашей записи по одному совпадению текста.
- Восстановление только при ожидаемой версии. Более новая копия пользователя
  не должна перезаписываться. Полный набор форматов Windows не гарантируется:
  неподдерживаемый формат приводит к отказу при сохранении, до вашей записи.
- HWND без усечения до Int32, PID, заголовок, класс и проверка активного окна.
  Проверка HWND/PID не является разрешением на вставку или защитой от любого
  повторного использования HWND; здесь нет отправки клавиш и автоматической вставки.

Нет зависимости от `ZBSWindowsComponent.dll`, Settings, Preview, WebView2,
провайдеров, ключей, VS Code, конфигов или работающего Make it ZBS.
Три внутренних core-файла компилируются из тех же исходников, что приложение,
а не поддерживаются как отдельная скопированная ветка. Их старый внутренний
namespace не является публичным API библиотеки.

DXGI/GDI, горячие клавиши, UIA-редакторы, HTTP/CLI и применение текста пока
не экспортируются. Для захвата следующим шагом нужно выделить независимый
контракт процесса/отмены, а не перенести весь оркестратор приложения в DLL.

## Использование

В бинарном пакете достаточно `OneScript.Windows.dll`. Движок предоставляет
сам OneScript; он не вкладывается и не заменяет вашу установку.
Фактически проверенный runtime: приватный `1.9.4-zbs.1` с исправлением ZIP.

```bsl
ПодключитьВнешнююКомпоненту("C:/path/OneScript.Windows.dll");
Буфер = Новый БуферWindows();
Исходник = Буфер.Сохранить();
ВерсияЗаписи = Буфер.ЗаписатьТекст("Временный текст", Исходник.Версия);
Восстановлен = Исходник.Восстановить(ВерсияЗаписи);
Исходник.Закрыть();
```

Всегда явно закрывайте снимки, включая ветвь исключения. `Закрыть()` освобождает
ресурсы, но **не восстанавливает буфер**. Сборщик мусора тоже не возвращает
старый буфер неожиданно поздно. `Восстановить` возвращает `Ложь`, если версия
уже изменилась; ошибка/гонка при открытии native-буфера остаётся исключением.
Не подставляйте текущую версию вслепую вместо версии собственной записи.
Неудачная Win32-запись/восстановление не обещает транзакционного отката Windows.
В конце работы хоста вызовите `Буфер.ЗавершитьСлужбы()` (`Shutdown()`), после
закрытия всех снимков. Это завершает общий STA-поток библиотеки. Повторный запуск
этой службы в том же AppDomain не поддерживается; не вызывайте Shutdown между
обычными операциями. Он не останавливает отдельную службу Make it ZBS.

| Русский API | English alias |
|---|---|
| `Новый БуферWindows()` | `New WindowsClipboard()` |
| `ПрочитатьТекст()`, `Версия` | `ReadText()`, `SequenceNumber` |
| `ВерсияСобственнойЗаписи` | `OwnedSequenceNumber` |
| `Сохранить()` | `Save()` |
| `ЗаписатьТекст(Текст, ОжидаемаяВерсия = -1)` | `WriteText(Text, ExpectedSequence = -1)` |
| `Снимок.Восстановить(ВерсияЗаписи)`, `Закрыть()` | `Snapshot.Restore(WriteSequence)`, `Close()` |
| `Новый РабочийСтолWindows().АктивноеОкно()` | `New WindowsDesktop().ForegroundWindow()` |
| `Дескриптор`, `ИдентификаторПроцесса`, `Заголовок`, `Класс`, `Активно()` | `Handle`, `ProcessId`, `Title`, `ClassName`, `IsForeground()` |

`-1` у записи означает явное разрешение перезаписать текущий буфер без сравнения
версий. Текст ограничен 4 млн UTF-16 символов; NUL запрещён, чтобы не получить
неявно усечённый текст. Ошибка чтения не маскируется под пустую строку.
Содержимое, заголовки и снимки автоматически не журналируются и не сохраняются.
`ВерсияСобственнойЗаписи` возвращает `-1`, если собственная запись больше
не подтверждается. Этот метод не присваивает чужой буфер по PID процесса или
совпадению текста. [Счётчик Win32](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getclipboardsequencenumber)
может учитывать отложенное представление данных; один ранний номер не доказывает
владение буфером после `CloseClipboard`.

## Сборка и тест

Из монорепозитория на Windows с SDK из `global.json`:

```powershell
dotnet build -c Release libraries/onescript-windows/OneScript.Windows.csproj
```

Исходный пакет содержит свои `core`, `vendor`, NuGet config и lock-файл.
Его можно собирать отдельно от Make it ZBS:

```powershell
dotnet build -c Release OneScript.Windows.csproj -p:RestoreLockedMode=true
```

`tests/smoke.os` запускается с путём DLL первым аргументом. Он работает с
синтетическими данными и восстанавливает исходный буфер, если тот не изменился.
Нужен свободный интерактивный рабочий стол, во время теста нельзя копировать.
Ни настоящий текст буфера, ни заголовок окна не выводятся. Примеры лежат в
`examples`. Установка через opm/NuGet registry пока не опубликована.
